# 공개 직후 운영 절차

## 0. 현재 확인된 사실과 미확정 항목

공고의 주제는 KAMP 제조AI 데이터셋으로 중소 제조기업의 공통 문제를 해결·개선하는 AI 모델 개발입니다. 장비 이상 조기 탐지, 품질 이상 탐지·진단, 공정 운영 최적화는 **예시**입니다. 공고문에는 50종 중 1종 또는 여러 종을 활용해 문제를 출제할 예정이라고 되어 있습니다. 2026-09-20 현재 공식 공지 목록에는 2026년 과제공개 글이 없습니다. 문제 발표·과제 해결 일정은 9/21~10/8입니다.

다음은 모두 공개 후에 확정합니다: 정확한 데이터 파일, 과제 유형, 예측 대상, 훈련/평가 데이터 구분, 평가 지표, 제출 형식, 외부 데이터·모델 허용 범위, 재현 환경.

## 2. 9/21 수신 즉시: 명령과 확인 순서

먼저 [공식 공지 목록](https://www.kamp-ai.kr/contestNoticeList)에서 2026년 **과제공개/문제발표** 게시물을 확인하고, 첨부 과제문·데이터 설명서·평가/제출 규칙을 읽습니다. 내려받은 원본 파일은 `data/incoming/`에 **그대로 복사**합니다. 링크만 보고 자동으로 오래된 대회 파일을 받지 않습니다. 예를 들어 Downloads에 받은 경우 실제 파일 이름을 확인하고, 파일별로 다음 명령을 실행합니다. `-n`은 기존 같은 이름의 파일을 덮어쓰지 않습니다.

```bash
cp -n '/Users/hamseongho/Downloads/실제_공식_파일명' data/incoming/
```

```bash
cd /Users/hamseongho/Documents/ChatGPT/KAMP
source .venv/bin/activate
python kamp_prep.py env --report reports/environment-20260921.json
python kamp_prep.py inventory data/incoming --report reports/inventory-20260921.json
python kamp_prep.py inspect 'data/incoming/실제_파일명.csv' --report reports/schema-20260921.json
```

`inspect`는 CSV, Parquet, XLSX, JSONL의 **앞부분만 샘플링**합니다. ZIP은 `inventory`로 내부 목록과 위험 경로 유무를 먼저 확인하고, 공식 안내에 맞춰 `data/working/`에 따로 해제한 후 각 실파일을 `inspect`합니다. 대용량 파일을 바로 전체 로드하지 않습니다. 경로의 `실제_파일명.csv`는 수신한 **실제 경로**로 바꿉니다.

확인 순서:

1. 과제문·데이터 설명서의 버전·공개일·수정 공지를 기록합니다.
2. 받은 파일명, 바이트 크기, SHA-256, 압축 내부 목록을 `inventory`에서 확인합니다.
3. 파일별 인코딩, 구분자, 시트, 열 이름·타입·결측·고유값 수를 `inspect`에서 확인합니다.
4. 행 단위가 무엇인지(제품/설비/시점/이미지), 중복 키, 시간 범위, train/test 간 겹침을 점검합니다.
5. 목표변수, 공식 지표, 평가용 데이터 접근 가능 여부, 제출 예시 파일을 확인합니다.
6. 공식 분할 규칙이 있으면 그대로 따릅니다. 없다면 시간 선후관계·설비/제품 묶음·중복 샘플 여부에 따라 분할을 정하고, 선택 근거를 기록합니다.
7. 그 후에만 `config/task.template.json`을 `config/task.json`으로 복사하고 실제 값을 입력합니다. 단순한 표 형태 지도학습일 때만 아래 CPU 기준선을 실행합니다.

```bash
cp config/task.template.json config/task.json
# 편집기로 config/task.json에 공개된 실제 경로·열·평가지표·분할 규칙을 입력
python kamp_prep.py baseline --config config/task.json
```

기준선은 실행마다 `reports/baseline-날짜시간/`에 데이터 해시·분할 해시·패키지 버전·점수·모델을 별도 저장합니다. `source_file`, `target_column`, `task_type`, `metric`, `split.strategy` 중 하나라도 미확정이면 실행을 거부합니다. 사용 가능한 일반 분할은 `random`, `stratified`, `group`, `time`이며 공식 분할이 제공된다면 이 명령 대신 공식 분할을 구현해야 합니다. 이미지/시계열/비지도 문제에도 이 일반 기준선을 억지로 적용하지 않습니다.

## 3. 입력 스키마 확인표

| 확인 항목 | 기록할 내용 |
| --- | --- |
| 파일별 역할 | 학습/평가/정답/제출 예시/설명서/보조 데이터 |
| 형식 | CSV 인코딩·구분자, Parquet 스키마, XLSX 시트, ZIP 내부 구조 |
| 행/열 | 전체 행 수(가능한 경우), 열 이름·순서·타입·단위, 중복 열 여부 |
| 키 | ID 열, 중복 여부, train/test 공통 키, 제품·설비·로트·시간 그룹 |
| 정답 | 타깃 열, 레이블 정의, 결측, 클래스 불균형 또는 수치 범위 |
| 누수 | 미래 시점 변수, 타깃 사후 생성값, 같은 제품/로트의 분할 간 중복 |
| 제약 | 외부 데이터/사전학습 모델·연산 환경·파일 크기·추론 시간 제한 |

`inspect`의 타입은 **샘플 기준 추정치**일 뿐이므로 전체 데이터·공식 설명서와 대조해야 합니다.

## 4. 결과 파일 검사 틀

공식 제출 예시와 규칙을 확인한 뒤 `config/task.json`의 `submission`을 채웁니다. CSV 제출인 경우에만 다음을 실행합니다.

```bash
python kamp_prep.py check-output outputs/실제_결과.csv --config config/task.json
```

검사 항목: 열 이름과 **순서**, 행 수, ID 중복 및 공식 제출 예시의 ID 순서, 예측값 공백, 지정한 수치열의 NaN/무한대, 지정한 허용 레이블. 제출 예시가 있다면 `reference_file`을 채우고, 없다면 `expected_columns`와 `expected_rows`를 공식 규칙에 맞춰 채웁니다. `prediction_columns`는 반드시 설정합니다. CSV가 아닌 제출 형식은 별도 검사기를 작성해야 합니다. **검사 통과는 대회 규정 준수나 점수 보장이 아닙니다.**
