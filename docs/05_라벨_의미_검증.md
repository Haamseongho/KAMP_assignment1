# `PassOrFail` 의미 검증 메모

2026-09-22 현재 상태: **이 대회 ZIP의 0/1 방향 미확정**. 모델은 `1=불량`을 작업 가정으로 학습했으나, 결과를 현장 검사 지시 또는 확정된 불량 성능으로 해석하면 안 된다. ZIP의 SHA-256은 `1fd8eccd9203374e1a0465d66acb5822c2fd3eec4084d2ca537d4155aa947ad7`이며, 내부 네 CSV의 해시는 [`data_audit.json`](../outputs/moldguard/data_audit.json)·[`reproducibility.json`](../outputs/moldguard/reproducibility.json)에 보존했다.

이 문서의 외부 출처는 **제3자 사이트에 게시된 가이드북 사본**이며, 2026년 대회 과제공개문이나 대회 ZIP 자체의 버전별 코드북이 아니다. 특히 한 가이드북 안에 서로 반대인 숫자 정의가 있으므로 어느 한 문장만 선택하여 현재 파일에 대입하지 않는다. 과제공개 HWPX는 문제를 정의하지만 이 네 CSV의 숫자 라벨 방향은 적지 않는다.

## 확정에 필요한 증거와 수신 후 판정

1. 2026년 대회 데이터 제공자에게 **네 파일명과 SHA-256을 지정하여** `PassOrFail`의 0/1과 실제 검사결과 대응표, 변환 이력, 결과 확정 시점을 요청한다. 일반적인 사출성형기 데이터 설명만으로 대체하지 않는다.
2. 원시 검사기록과 연결 키를 받을 수 있다면 CN7·RG3의 서로 다른 0/1 행을 각 여러 건씩 대조한다. 제품·샷·캐비티 단위가 다른 경우 그 관계도 확인한다.
3. `1=불량`이 확인되어도 기존 수치의 **라벨 의미만** 확정된 것이다. 파일 전체 정규화와 예측 시점 문제를 별도로 검증하고, 새 기간의 독립 라벨에서 성능을 다시 평가한다.
4. `0=불량` 또는 파일별 방향 차이가 확인되면 현재 불량 AP·발견율·위험순위·오류해석은 폐기한다. 라벨 변환, 그룹 층화 분할, 모델 학습, 검증, 추론 파일을 모두 다시 생성한다. 이미 들여다본 기존 홀드아웃을 새 모델의 독립 검증으로 사용하지 않는다.
5. 판정 전에는 [`unlabeled_priority.csv`](../outputs/moldguard/unlabeled_priority.csv)의 `priority`·`risk_score`를 **오프라인 분석값**으로만 보며, `action`은 모든 행에서 기존 검사를 유지하도록 한다.

최종 제출은 이 메모나 분석 코드가 자동으로 수행하지 않는다. 전달 방식은 사용자가 별도로 정한다.
