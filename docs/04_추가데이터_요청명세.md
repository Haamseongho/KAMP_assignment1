# 사출성형 후속 검증용 데이터 계약

현재 CSV만으로는 RG3 성능과 최종검사 이전 정보 가용성을 입증할 수 없다. 아래는 **추가로 요청할 필드와 검증 조건**이며, 존재하지 않는 데이터를 만들거나 현재 파일의 인덱스를 시간·캐비티 ID로 간주하지 않는다.

| 필수 정보 | 필요한 이유 | 수신 즉시 검사 |
| --- | --- | --- |
| **현재 ZIP의 파일명·SHA-256에 대응하는** `PassOrFail`의 0/1 코드북, 변환 이력, 불량 판정 기준·확정 시점 | [가이드북 내 상반된 0/1 설명](05_라벨_의미_검증.md)을 현재 CSV에 적용할 수 없어 양성 클래스의 의미 확정 필요 | CN7·RG3 각각 코드값과 실제 검사 결과를 여러 행 대조 |
| 제품·캐비티·샷을 구분하는 키와 관계 | 동일 센서값·상반 라벨 36그룹의 원인 확인 | 각 제품이 어느 샷/캐비티에서 나왔는지 1:N 관계 검증 |
| 샷 시작·종료, 변수별 시스템 도착, 검사 시작·확정 시각(타임존 포함) | 예측 시점의 누수 방지와 전방검증 | 사용 변수의 도착 시각이 예측 cutoff 이전인지 행별 확인 |
| 정규화 전 원시 변수·단위·센서/설정값 구분, 기존 변환기 | 신규 샷 추론과 물리적 해석 | 변환기를 훈련 기간에만 적합했는지, 신규 기간에 재적합하지 않았는지 확인 |
| CN7·RG3 각각의 **후속 기간** 라벨 결과 | 진짜 미래 성능·드리프트 확인 | 기간 중복·동일 샷 중복을 차단하고 설비별 불량 수 확인 |

검사 대기열의 효과까지 검증하려면 제품의 검사 가능 시각, 실제 검사 시작·종료 시각, 검사 인원/장비 수, 필수·긴급검사 규칙도 필요하다. 이것이 없으면 정적 Top-K 발견율까지만 보고할 수 있고, 시간 절감·비용 절감·작업환경 개선 수치는 산출하지 않는다.

## 수신 시 적용할 중단조건

1. 라벨 방향이 미확정이면 불량 예측 성능·우선순위 효과를 확정하지 않는다. `priority`는 오프라인 참고값이며 `action`은 모든 행에서 기존 검사를 유지한다.
2. 키 연결이 불명확하거나 같은 제품에 상충하는 최종 판정이 있으면 행을 임의로 삭제·정상 처리하지 않고 별도 원인 목록으로 분리한다.
3. 입력 변수가 예측 cutoff 뒤에 도착하면 그 변수를 제거하고 **분할부터 다시** 수행한다.
4. 새 기간을 모델/임계값/우선순위 선택에 사용하지 않는다. 시간·샷 그룹을 분리해 개발·보정·최종 평가 영역을 먼저 고정한다.
5. RG3의 새 기간 성능이 검증되기 전에는 `action=usual_inspection_unvalidated_machine`을 유지한다. CN7도 현장 승인 전에는 시뮬레이션 결과로만 사용한다.

원본 추가 파일은 원형과 SHA-256을 함께 보관하고, 변환 사유·제외 행·실행 명령·패키지 버전·검사 결과를 재현 로그에 남긴다. 새 데이터를 받은 뒤 기준선, 로지스틱/트리 후보, 설비별 발견율과 오경보, OOD, 실제 대기열 재생을 같은 전방분할에서 비교한다.
