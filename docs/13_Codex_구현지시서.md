## 3. 패치 단위와 완료 기준

### Patch A — 재현 경로 복구: MG-002

기존 CLI와 호환되는 선택 인자 `--data-dir`, `--split-dir`, 필요한 `--output-dir`을 추가한다. 과거 기본 경로는 가능하면 유지하되 없는 경로에서는 해결 가능한 명시적 오류를 낸다.

분할만 생성하는 명령을 구현한다. 실제 명령 이름은 기존 CLI와 맞춰 선택하고 README에 검증된 명령을 쓴다. 명세에 적힌 예시 파일명이 곧 존재하는 실행 파일이라는 가정을 하지 않는다.

분할 검사:
- 원본 파일/스키마/라벨/그룹/seed의 해시와 규칙 기록.
- 동일 설비·동일 원본 24개 공정값 그룹의 train/validation/holdout 교차 금지.
- 현재 데이터의 특징 선택이 그룹 키를 바꾸지 않도록 분리.
- 행 단위 입력/라벨/원본 ID와 split manifest 일치.
- 과거 기준 분할이 있으면 해시와 행 배정 비교.
- 과거 분할을 입수하지 못하면 새 분할로 표시하고 수치 동일 재현을 주장하지 않음.
- 학습 없는 분할 생성은 모델 파일을 교체하지 않음.

시험은 데이터 없는 단위시험과 공식 데이터 통합시험을 분리한다. 실제 데이터가 없으면 결과 검사를 통과로 처리하지 않는다.

### Patch B — 데이터 계약: MG-003

계약 스키마와 저장을 구현한다. 각 항목은 상태, 적용 데이터 해시/원천, 증거, 검토자, 확인일, 버전을 가진다. 최초값은 `unconfirmed`다.

제안 항목: `label_semantics`, `target_unit`, `product_shot_cavity_mapping`, `feature_availability`, `inspection_timing`, `raw_units`, `supplier_transform`, `future_validation_data`.

LegacyResearch와 Operational 스키마를 분리한다. 레거시에서는 미확인 시각을 null로 두고 분석할 수 있지만 Operational에서는 필수 계약이 없으면 수신/추천 경로가 차단돼야 한다.

요청 body의 `confirmed=true`로 계약 승인을 우회하지 못하게 한다. 실제 계약 확인 권한과 추론 요청 권한을 분리한다. 아직 인증을 구현하지 않은 로컬 데모라면 현장 승인 API를 비활성화한다.

### Patch C — 정책 엔진: MG-004

핵심은 순수 함수 또는 작게 시험 가능한 모듈로 구현한다.

입력: 데이터 유효성, 확인된 계약 상태, 연구/운영 모드, 서버의 범위별 승인, OOD/지연/모델 상태, 연구 점수.
출력: 연구 점수, 연구 순위, 운영 추천 여부, 기존 검사 action, 모든 차단 사유, 버전 정보.

중요한 규칙:
- `defect_probability`는 검증된 확률 승인이 없으면 null.
- RESEARCH_ONLY/SHADOW는 운영 추천을 허용하지 않음.
- 현재 RG3는 기존 `usual_inspection_unvalidated_machine`을 보존.
- 현재 CN7 OOD는 `usual_inspection_ood`, 나머지는 `usual_inspection_label_unconfirmed`를 보존.
- 현재 CN7의 현장 미승인 사유도 reasons에 남기되 과거 action 호환성을 깨지 않음.
- 누락/NaN/Inf/추론 실패는 risk=0이 아니라 오류/미산출.
- 추천 불가를 기존 대기열의 최하위 배치로 해석하지 않음.
- 승인 만료·철회·대상 범위 불일치면 신규 결정은 즉시 fallback.
- 현재 권한 수준에서 새 경고가 추가되면 운영 권한이 상승할 수 없음.
- 검사 생략, 자동 합격, 자동 온도/압력 변경, 설비 정지 명령은 생성하지 않음.

초기 구현에서는 ADVISORY_APPROVED의 상태 구조/차단 테스트까지만 만들고 실제 활성화하지 않는다. 정책 JSON 예시는 런타임 구현물로 간주하지 말고 필요한 스키마 검증기를 함께 작성한다.

### Patch D — 어댑터와 연구 조회: MG-005

기존 모델/추론/산출물을 읽는 어댑터를 구현한다. 먼저 파일 존재·스키마·버전을 검증한다. 존재하지 않는 출력을 ‘예시 실적’으로 채우지 않는다.

화면 최소 범위는 데이터 준비 상태와 연구용 순위다. 상단에 ‘연구용 / 실제 검사 변경 없음’을 고정 표시한다. 점수 대상은 숫자 라벨 1이며 확률이 아님을 명시한다. 없는 값은 ‘미확인/미산출’로 표시한다.

실험 결과 파일이 준비되면 전체/CN7/RG3 지표로 연결할 API 기반을 만든다. 문서상 집계값은 필요 시 ‘기존 보고서 기록’이라는 별도 설명 패널로만 쓸 수 있고, 실제 run 결과와 섞지 않는다.

DB가 필요하면 기존 것을 재사용한다. 없으면 로컬 데모용 최소 영속 저장부터 만든다. 처음부터 다중 서비스/GPU/LLM 연동을 도입하지 않는다.

## 4. 두 번째 개발 배치

첫 배치가 검증된 뒤 진행한다.

**MG-006:** 실패조건 화면. 지표 정의, 평가 범위, 행·그룹·양성 수, 임계값 기반 오류와 Top-K 밖의 양성 구분, 사후 발견 조건 표시.

**MG-007:** 사건·점검표·조치 이력. 실제 SOP 미수신 시 템플릿 상태. 승인되지 않은 설정값/원인 설명을 생성하지 않는다. 수정·종료·정정은 사유와 버전을 남긴다.

**MG-008:** 실험 계획을 먼저 config로 고정한 뒤 H1–H4 중 예산 내 후보만 비교한다. 비교는 내부 선택/외부 평가를 분리하고 과거 기준선을 보존한다. 새 모델이 더 나쁘면 기준선 유지 결정을 기록한다.

## 5. 데이터 수신 후 개발 배치

**MG-009~011:** 실제 샷/제품/캐비티, 시각, 원시 단위/변환기, 새 기간 라벨이 들어온 뒤 계약 검증부터 수행한다. 승인 없는 데이터를 넣었다고 연구 모드가 자동으로 현장 모드로 바뀌지 않는다.

전방검증은 과거 학습→선택/보정→미래 평가를 먼저 동결한다. 대기열 재생은 현행/FIFO와 같은 도착·자원·규칙 조건에서 수행하고, 아직 도착하지 않은 미래 제품이나 최종 라벨을 스케줄링 입력에 쓰지 않는다.

새 평가를 보고 임계값을 다시 고르면 해당 기간은 선택 데이터로 바뀐 것이다. 새 독립 최종 기간을 확보하거나 한계를 명확히 보고한다.

**MG-012:** 반복 사건·공정 중 예측은 별도 시점 계약의 연구다. 현재 CSV의 인덱스를 시간으로 쓰는 우회 구현은 하지 않는다.

## 7. 완료 보고 형식

최종 작업 보고서는 다음 순서로 작성한다.

1. **구현 범위:** 티켓별 완료/부분완료/미구현. 코드가 있는 것과 현장 검증을 구분.
2. **변경 파일:** 각 파일의 이유, 과거 API/산출물에 미친 영향.
3. **실행 명령:** 실제 성공한 설치·단위시험·통합시험·실행 명령만.
4. **테스트 결과:** passed/failed/skipped 수, 생략 이유, 데이터 없는 검사의 범위.
5. **재현 비교:** 입력/분할/코드 해시, 지표/허용 오차, 다르면 원인.
6. **운영 상태:** RESEARCH_ONLY, 기존 검사 유지, 비활성 기능과 사유.
7. **남은 조건:** 실제 필요한 파일/데이터/승인과 다음 개발 티켓.

수치 개선을 확인하지 못했으면 ‘개선 없음/불확실’로 보고한다. 구현한 인터페이스·단위시험을 현장 효과 검증으로 바꿔 쓰지 않는다.

## 8. 완료 산출물 제안

- 실제 경로에 맞게 수정한 README와 검증된 로컬 실행 명령.
- 데이터 계약·정책·어댑터·읽기 전용 화면/API 코드.
- 단위/통합/인수 테스트의 분리와 결과 보고.
- 새 run_manifest, 입력/분할/모델/정책 해시, 검증 로그.
- 모델/정책 채택 또는 보류의 결정 기록.
- 외부 데이터 없이도 열리는 빈 상태 화면.
- 미검증 기능이 실제로 비활성화되는 회귀시험.
