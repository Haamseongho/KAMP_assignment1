# MoldGuard — 인수테스트 및 데모 시나리오

작성일: 2026-09-26 · 상태: **시험 설계, 아직 실행한 결과 아님**

## 1. 시험 레이어

| 레이어 | 입력 | 보증 범위 |
|---|---|---|
| Unit | 계산/정책용 최소 고정 fixture | 함수·상태 전이·스키마·권한 제한 |
| Integration | 실제 공식 CSV·고정 분할·모델 산출물 | 추론/지표/해시/레거시 호환 |
| Acceptance | 애플리케이션·계약·권한·저장 | 실제 UI/API 동작과 불변조건 |
| Future validation | 미사용 미래 기간 데이터 | 범위별 모델 일반화 검토 |
| Operational evaluation | 실제 대기열/작업/조치 기록 | 정책·업무 효과 평가 |

단위시험 fixture는 `TEST_ONLY`로 구분하고 실제 제조 데이터·대회 성능 산출에 사용하지 않는다. 시간 검증용 fixture의 시각은 ‘코드 시험용 값’이며 현재 CSV의 실제 시각을 복원한 값이 아니다.

## 3. 평가규약 회귀시험

전체 Top-K, 설비별 Top-K, fold×설비별 Top-K를 다른 지표명으로 저장한다. 각 N·K·회수 수를 검증한다. 프로토콜이 바뀌면 과거 지표를 재정의해 덮어쓰지 않는다.

확률보정 비교에서 원점수/보정값/발생률 상수를 분리한다. AP/Brier/Log loss와 신뢰도 구간·표본 수를 함께 출력한다. 양성이 없는 평가나 bootstrap 반복의 처리 규칙을 검사한다.

새 독립 평가셋의 경로가 개발 튜닝에 전달되면 실패하도록 검증하는 방식을 제안한다. 최소한 run manifest에서 사용 범위가 확인돼야 한다. 숨겨진 탐색이 없다는 통계적 보증을 테스트 하나로 주장하지 않는다.

## 4. 데이터가 없는 상태의 시연

① 준비 상태 화면에서 ‘공식 CSV/분할/모델 산출물 없음’을 보여준다.

② 입력/모델/계약이 없으면 점수·확률·운영 우선순위가 미산출임을 보여준다.

③ TEST_ONLY 정책 시험 화면에서 라벨 미확정, RG3, OOD, 입력 오류 경로가 기존 검사로 복귀함을 보여준다. 이를 실제 생산 기록으로 꾸미지 않는다.

④ 미승인 SOP 템플릿과 필요한 데이터 요청 목록을 보여준다.

⑤ 실행한 단위시험과 생략된 실제 데이터 통합시험의 범위를 구분해 설명한다.

## 5. 실제 과거 산출물이 있는 상태의 시연

① 원본·분할·실행 해시와 연구 모드 상태를 확인한다.

② 전체 개발 OOF AP와 CN7/RG3 차이를 보여준다. 과거 홀드아웃 수치와 같은 표본처럼 합치지 않는다.

③ 연구용 순위의 HIGH가 실제 우선검사 승인과 다름을 보여준다.

④ RG3·OOD·라벨 미확정에 대한 action/reasons를 확인한다.

⑤ 조건별 오류 표에서 표본 수와 한계를 설명하고, ‘원인 확정’ 대신 ‘점검 요청 템플릿’으로 연결한다.

⑥ 추가 데이터 수신 후 어떤 평가가 활성화되는지 보여준다. 시간 절감·불량률 감소는 미검증으로 남긴다.

## 6. 현장 SHADOW/재생 시연 — 추가 데이터 이후

당시 도착한 입력과 실제 검사 결과를 분리해 재생한다. SHADOW 결과가 기존 큐를 바꾸지 않는지 확인한다. 현행/FIFO와 AI 보조 정책을 동일 도착·자원·규칙에서 비교하고 전체 대기·설비별 지연·필수 규칙 준수를 함께 보여준다.

소요시간 고정 등 반사실 가정을 명시한다. 재생에서 후속 불량을 삭제하거나 생산량을 임의 변경하지 않는다. 검사 발견 시간의 차이와 실제 예방 효과를 구분한다.

## 7. 시험 보고 파일 필드

`test_id`, `layer`, `status`, `input_hash`, `code_hash`, `policy_hash`, `executed_at`, `command`, `exit_code`, `reason`, `evidence_path`.

상태는 `passed / failed / skipped / not_implemented`를 구분한다. 연구/현장 검증 단계도 별도 필드로 기록한다. 문서에 적힌 시험 목록의 존재 자체가 시험 통과의 증거는 아니다.
