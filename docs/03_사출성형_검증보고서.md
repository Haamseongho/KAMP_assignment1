# MoldGuard — 사출성형 불량위험 예측·검사 우선순위 검증 보고서

2026-09-22, 고정 분할 실험 초안. 이 문서는 **실제 제공된 네 CSV**에 대한 실행 결과이며, 제출 양식의 제1~6장(15·40·15·10·10·10점)에 맞추어 작성했다. 원본은 수정하지 않았다. 파일 해시·명령·패키지 버전은 [`reproducibility.json`](../outputs/moldguard/reproducibility.json)에 남겼다.

> **판정 요약:** 동일 공정값의 학습·평가 교차는 차단한 재현 가능한 기준선과 비교 실험을 완성했다. 다만 제공 CSV의 라벨 코드와 사전 정규화 범위를 확정할 수 없어 **완전한 누수 방지·현장 불량 예측 성능을 입증한 것은 아니다.** 특히 RG3의 낮은 검증 성능, 서로 다른 라벨의 동일 센서값, 비라벨 데이터의 분포 차이 때문에 **모든 제품의 기존 검사는 유지**해야 한다. 모델의 검사 순위는 오프라인 시뮬레이션이며 검사 생략·자동 제어에 쓰지 않는다.

## 1. 데이터 이해 및 진단〔15점〕

### 과제와 예측 시점

공식 과제공개 HWPX의 ① 문제는 “사출성형 공정데이터 기반 품질불량 사전예측 및 검사 우선순위 결정”이다. 공정 종료 후 최종검사 *이전*의 공정 요약값으로 불량을 예측하고, 정확한 조건과 실패 조건을 분석하도록 요구한다. 따라서 이 구현은 “제작 전 결과 예측”이나 “진행 중 조기경보”가 아니다. `Cycle_Time` 등 샷 전체 요약이 포함되므로 **공정 종료 후·최종검사 전**만을 검증 가능한 예측 시점으로 잡았다. 검사 결과인 `PassOrFail`과 출처 인덱스 `Unnamed: 0`은 입력에서 제외했다. 원본의 실제 수집 시각·검사 확정 시각·각 변수의 도착 시각은 제공되지 않아 최종검사 전 가용성은 현장 데이터 계약으로 추가 확인해야 한다.

실험은 `PassOrFail=1`을 불량으로 **가정**한다. 1이 소수 클래스(42/2,393)이고, [KAIST 주관 사출성형기 분석실습 가이드북의 모델링 단계](https://www.scribd.com/document/1020891218/04-Guidebook-Molding)는 양품 `Y→0`, 불량 `N→1`로 재부호화해 설명한다. 하지만 같은 가이드북의 데이터 속성표에는 `0=불량, 1=양품`이라고 **반대 방향**으로 적혀 있다. 이 가이드북은 제3자 사이트에 올라온 사본이며 현재 대회 ZIP의 정확한 파일 버전·전처리 이력·SHA-256과 연결하는 근거가 없다. 따라서 다수/소수 비율이나 파일명만으로 **현재 CSV의 라벨 방향을 확정할 수 없다.** 이 보고서의 “불량”과 모든 성능·우선순위 해석은 해당 가정에 조건부다. 증거와 판정 절차는 [라벨 의미 검증 메모](05_라벨_의미_검증.md)에 정리했다.

라벨 데이터 합계 2,393행, 불량 가정 42행(1.755%), 비라벨 71,180행이다. 라벨 파일에는 ID·라벨·수치 공정변수 24개, 비라벨 파일에는 ID·같은 수치변수 24개가 있다. 필수열·열 순서·숫자형·유한값·ID 중복을 검사했다. 네 파일 모두 결측은 없었다. `Clamp_Open_Position`은 라벨 데이터에서 상수이므로 모델 입력에서 제외했다. 모델 입력은 나머지 공정변수 23개와 설비 표시 1개이다. 세부 스키마와 원본 SHA-256은 [`data_audit.json`](../outputs/moldguard/data_audit.json)에 있다.

중대한 품질 제약은 **동일한 24개 센서값을 가진 행이 라벨 데이터에서 거의 두 번씩 나타난다는 것**이다. 전체 1,197개 동일 관측값 그룹 중 36개는 한 행이 정상(0), 다른 행이 불량(1)이다. 42개 불량 중 36개가 이 모순 그룹에 속한다. 제공된 입력만 보는 결정적 분류기는 이 두 행을 구분할 수 없으므로, 관측된 데이터 자체에 최소 36/2,393의 불가분 오류가 있다. 이를 데이터 오류로 단정하지 않는다. 다중 캐비티·샷 단위 센서와 제품 단위 검사 결과의 연결일 수도 있으나, 캐비티/제품 ID가 없어 확인할 수 없다. **정확도 98%대는 항시 정상 예측만으로도 달성되므로 주요 지표로 쓰지 않는다.**

네 파일 각각에서 변동하는 변수의 평균은 부동소수점 오차 범위의 0, 모표준편차는 1이다([`data_audit.json`](../outputs/moldguard/data_audit.json)의 파일별 검증값). 즉 파일마다 별도로 정규화된 것으로 보인다. 원시 단위·변환기의 학습 범위·원본 스케일러는 제공되지 않았다. 따라서 바렐 온도·압력 등의 계수에서 물리적 최적 범위를 역산하지 않는다. 출처 인덱스는 시간으로 검증되지 않았으며, CN7의 불량 17건이 인덱스 앞 20%에 모두 몰려 있다. 뒤 20%에는 불량이 0건이다.

## 2. AI 예측모델 개발 및 성능평가〔40점〕

### 누수 방지와 비교 조건

같은 설비의 **완전히 동일한 공정변수 벡터**를 하나의 그룹으로 묶고, 그룹이 학습·평가 양쪽에 걸치지 않도록 했다. `machine × 그룹 내 라벨 1 존재` 층화로 80% 개발/20% 최종 홀드아웃을 고정했다(`seed=20260922`). 실제 분할은 개발 957그룹·1,913행·라벨 1이 33행, 홀드아웃 240그룹·480행·라벨 1이 9행이다. 개발 내부에서만 5-fold 그룹 단위 OOF(out-of-fold) 예측을 만들었다. 후보를 **개발 OOF 평균정밀도(AP)**로 선정한 뒤 첫 홀드아웃 평가를 했다. 같은 분할·입력·지표를 모든 후보에 적용했다. 출처 인덱스, 라벨, 비라벨 데이터는 지도학습 특징에 사용하지 않았다. **단, CSV가 이미 파일 전체 기준으로 표준화된 듯하므로 전처리 단계까지 학습기간만 사용했다고 보증할 수 없다.** 여기서 확인된 것은 동일 입력의 교차 누수 차단이지 모든 형태의 누수 부재가 아니다.

| 후보 | 개발 OOF AP | 개발 Top 10% 불량 발견/전체 | 개발 ROC-AUC |
| --- | ---: | ---: | ---: |
| 항상 사전비율 예측(Dummy) | 0.0166 | 2/33 | 0.482 |
| 가중 로지스틱 회귀(선정) | **0.1154** | 9/33 | 0.758 |
| Random Forest | 0.0646 | 13/33 | 0.770 |
| CatBoost | 0.0546 | 9/33 | 0.724 |
| 설비별 로지스틱 회귀 | 0.0803 | 13/33 | 세부 JSON 참조 |
| 설비별 Random Forest | 0.0749 | 10/33 | 세부 JSON 참조 |
| 설비별 CatBoost | 0.0983 | 14/33 | 세부 JSON 참조 |

깊은 모델이 반드시 유리하지 않았다. 이 작은·희소·모순 라벨 데이터에서는 가중 로지스틱 회귀가 사전 고정한 선정 기준(AP)에서 가장 좋았다. 설비별 CatBoost는 개발 Top 10% 발견 수가 더 좋았으나 AP가 낮아 최종모델로 바꾸지 않았다. **홀드아웃을 보고 다시 모델이나 파라미터를 고르지 않았다.** CatBoost·Forest는 강한 비선형 비교 후보이지만 검증 우위가 입증되지 않았다.

첫 홀드아웃 결과를 본 뒤 별도 그룹 단위·설비별 조합을 탐색적으로 점검한 이력이 있다. 그 결과로 최종모델을 바꾸지는 않았지만, **이 홀드아웃은 앞으로 설계할 새 모델의 미사용 독립 평가셋이 아니다.** 향후 개선 성능은 새 기간의 별도 라벨 데이터에서 검증해야 한다.

개발 OOF를 설비별로 나누면 선정 로지스틱의 AP는 CN7 0.286, RG3 **0.023**(RG3 유병률 0.021)이다. RG3에서 가장 높았던 Random Forest도 AP 0.056, 설비별 Top 10% 발견 5/20이었다. 따라서 RG3 실패는 최종 홀드아웃에서 갑자기 드러난 우연만은 아니다. 전체 AP가 높은 모델을 선택했다는 사실과 *모든 설비에서 쓸 수 있다*는 결론을 분리한다. 후보별 설비 OOF 값은 [`experiment.json`](../outputs/moldguard/experiment.json)에 전부 기록했다.

## 3. 영향요인 및 오류분석〔15점〕

진단 임계값의 미탐 4건은 **모두 RG3**이다. 오경보 113건 중 RG3가 85건, CN7이 28건이다. 홀드아웃 불량 9건 중 7건은 동일 입력·상이 라벨 그룹에 속한다. 별도 목록: [`false_negatives.csv`](../outputs/moldguard/false_negatives.csv), [`false_positives.csv`](../outputs/moldguard/false_positives.csv). 어떤 한 행의 오류가 센서 때문인지 캐비티/검사 연결 때문인지 현재 파일만으로 구별할 수 없다.

학습된 로지스틱 모델에서 큰 연관 계수는 설비 표시, `Clamp_Close_Time`, `Max_Switch_Over_Pressure`, `Max_Injection_Pressure` 등이다. 이는 **표준화 데이터의 예측 연관성**이며 공정조건 변경의 인과효과 또는 안전 범위가 아니다. 계수 전체는 [`failure_analysis.json`](../outputs/moldguard/failure_analysis.json)에 남겼다.

인덱스를 순서 대용으로 둔 별도 스트레스 테스트에서도 그룹 누수를 막았다. CN7의 마지막 20%는 불량이 0건이라 AP·재현율을 계산할 수 없다. RG3 마지막 20%는 불량 5건, AP 0.0423, Top 10% 발견 1/5이다. 이는 엄격한 시간검증이 아니다. **인덱스가 실제 시간인지 미확인**이고 각 파일 정규화에 미래 데이터가 섞였을 수 있다.

“비라벨 데이터를 이용한 이상 탐지라면 RG3이 개선될까?”도 개발 데이터만으로 점검했다. 동일 관측값을 한 그룹으로 합쳐 *그룹 내 하나라도 불량*을 양성으로 정의하고, 정상 그룹만으로 Isolation Forest를 5-fold OOF 학습했다. RG3의 그룹 단위 AP는 **0.041**, 양성 그룹 비율은 **0.042**로 우연 수준이다. 이는 원래 행 단위 과제와 다른 탐색적 단위이므로 위 모델 표와 직접 비교하지 않으며, 현재 입력만으로 비지도 이상점수에 기대어 RG3 성능을 주장하기 어렵다는 진단에 한정한다.

비라벨 데이터는 라벨 데이터와 큰 분포 차이가 있다. 설비별 변수 KS 통계량의 중앙값은 CN7 0.350, RG3 0.312다. 개발 데이터의 설비별 0.1~99.9 백분위 범위 밖인 변수가 3개 이상인 비라벨 행은 **27,357/71,180(38.43%)**이다(CN7 19,607; RG3 7,750). 이 정의는 이상 탐지의 경험적 경고선일 뿐 진짜 결함·오류의 증거가 아니다. 비라벨에는 정답이 없으므로 그 71,180행의 실제 성능·절감액·발견 시간 단축은 계산할 수 없다.

## 4. 현장 활용방안〔10점〕

현재 MVP는 샷 종료 후·검사 전 각 설비별로 검사 가능한 제품을 점수순으로 정렬한다. CN7·RG3 각각 상위 10%를 `HIGH`, 다음 10%를 `REVIEW`, 나머지를 `STANDARD`로 **참고 표시**한다. 설비별 할당을 쓴 이유는 전체 점수순만 쓰면 한 설비가 검사 자원을 독점할 수 있기 때문이다. **전량 필수검사는 유지**한다. 이미 긴급검사·현장 규칙이 있다면 AI 점수보다 우선해야 한다.

추론 파일 [`unlabeled_priority.csv`](../outputs/moldguard/unlabeled_priority.csv)는 71,180행 전부에 `machine`, 원본 `source_row_id`, `risk_score`, 전체·설비별 순위, `priority`, `ood_feature_count`, `ood_flag`, `action`을 포함한다. OOD로 표시된 행은 총 27,357개다. 성능 미검증 RG3 **35,941행 전부**는 `action=usual_inspection_unvalidated_machine`으로 복귀하며, CN7의 OOD **19,607행**은 `action=usual_inspection_ood`로 복귀한다(RG3 OOD 7,750행은 첫 규칙에 포함). 나머지 CN7 **15,632행**도 라벨 방향을 확정하지 못했으므로 `action=usual_inspection_label_unconfirmed`로 복귀한다. 즉 **모든 행의 실제 검사 흐름은 종전대로**이며 `priority`는 오프라인 분석용 순위에 불과하다. 추론 장애·스키마 불일치·누락 시에는 파일 생성이 실패하게 했으며, 실패를 0% 위험으로 치환하지 않는다. 실제 검사 자원·도착 시각·검사 소요시간이 없으므로 절감액이나 리드타임 단축을 주장하지 않는다.

## 5. 창의성 및 차별성〔10점〕

이 작업의 차별점은 특정 복잡한 모델 이름이 아니라 (1) 동일 관측값의 상충 라벨을 발견하고 분할 누수를 원천 차단한 점, (2) 전체 평균 뒤에 숨은 설비별 실패와 인덱스 순서 스트레스를 별도로 공개한 점, (3) 비라벨 대량 추론의 분포 차이를 자동 경고로 연결한 점, (4) 검사 생략이 아닌 **설비별 역량 제한 대기열 + 기존 검사 복귀**로 의사결정을 제한한 점이다. 각각의 가치는 제2·3장의 숫자로 검증되며, 미확인 경제효과나 물리적 불량 방지 효과를 주장하지 않는다.

## 6. 코드 구성 및 재현성〔10점〕

Python 3.12 CPU 경로에서 다음 순서로 실행한다. 원본 CSV 네 개를 같은 데이터셋 디렉터리에 두고, 파일 이름을 바꾸지 않는다. `requirements-model.txt`의 고정 패키지를 설치한다.

```bash
cd /Users/hamseongho/Documents/ChatGPT/KAMP
python3.12 -m venv .venv-repro
.venv-repro/bin/python -m pip install -r requirements-model.txt
.venv-repro/bin/python moldguard.py audit --output-dir outputs/moldguard
.venv-repro/bin/python moldguard.py train --output-dir outputs/moldguard
.venv-repro/bin/python analyze_moldguard.py
.venv-repro/bin/python moldguard.py verify --output-dir outputs/moldguard
.venv-repro/bin/python -m pytest -q
```

실험 코드 [`moldguard.py`](../moldguard.py), 독립 진단 [`analyze_moldguard.py`](../analyze_moldguard.py), 테스트 [`tests/test_moldguard.py`](../tests/test_moldguard.py)이다. `audit`가 원본 네 파일의 SHA-256·스키마·라벨 1/모순 그룹을 기록한다. `train`이 고정 분할, 7개 후보 비교, 최종 모델·홀드아웃 진단·비라벨 추론을 순서대로 생성한다. `verify`는 행 수·ID 보존·점수 범위·순위·우선순위·OOD·라벨 미확정 시 기존 검사 복귀를 검사한다. 두 번째 독립 실행에서 `experiment.json`, `holdout_diagnostics.csv`, `unlabeled_priority.csv`의 SHA-256이 모두 같았다. **새 가상환경에서 패키지를 설치해 다시 실행한 결과도 주요 JSON·CSV·그림의 SHA-256이 동일했다.** 이번 안전복귀 변경 후 세 환경의 추론 CSV 해시도 같으며 자동 테스트 **11/11 통과**했다. 정확한 패키지 목록·출력 해시·검사 로그는 [`pip-freeze.txt`](../outputs/moldguard/pip-freeze.txt) 및 [`reproducibility.json`](../outputs/moldguard/reproducibility.json)을 참조한다.

### 결과 확정·현장 적용 전 중단조건

1. 이 대회 ZIP의 정확한 네 CSV에 적용된 `PassOrFail` 0/1 코드북과 검사 결과가 제품·캐비티·샷 중 어느 단위인지 공식 자료 또는 현장 담당자로 확인한다. 지금은 `1=불량` 가정이다. 확인 전에는 CN7도 오프라인 순위로만 취급한다.
