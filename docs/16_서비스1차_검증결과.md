RESEARCH_ONLY를 유지한다. 확률과 운영 우선순위는 null이며 실제 검사·설비 시스템을 변경하지 않는다. 모델을 새로 선정하지 않았고 대회 제출, 원격 push, 외부 게시도 수행하지 않았다.

## 2. 변경 파일과 호환성

- `task01_compare.py`, `calibration_diagnostics.py`: 기존 계산과 기본 경로를 보존하고 `--data-dir`, `--split-dir`, 실행 영수증을 추가했다.
- `research_split.py`, `research_verify.py`, `research_runtime.py`: 분할 생성/검증, OOF 식별자·지표 검산, 명령·환경·해시·종료 상태 기록.
- `service_inventory.py`, `service_checks.py`, `verify_clean_reproduction.py`, `verify_service_release.py`, `service_probe.py`: 조사, 시험 계층, 새 환경 재현, 기존 파일 보존·수치 동등성, 실제 로컬 API 점검.
- `moldguard_service/`, `service_contract.py`, `config/service_policy.json`: 계약 저장, 정책, 기존 결과 어댑터, 로컬 API·화면.
- `tests/conftest.py`, `tests/test_service_*.py`, `pytest.ini`: 정책/통합/API 시험과 데이터 없음의 명시적 생략.
- README, 최상단 서비스 가이드·고도화 안내, docs/15~16: 실행법·검증 결과·후속 작업 구분.
- `.gitignore`: 로컬 가상환경과 계약 기록 제외. 원본 데이터와 행 단위 결과는 계속 공개 대상에서 제외한다.

기존 `moldguard.py`의 모델 계산과 사용자가 추가한 명세·예시 JSON·출처 manifest는 변경하지 않았다. 코드·환경·출력 해시는 각 실행 폴더의 `execution.json`에 있으며, 과거 결과의 실행 시각/코드 해시까지 동일하다고 주장하지 않는다.

### 실패와 수정 기록

첫 격리 실행 `clean/`은 CPU 비교까지 완료했으나 pytest가 상위 폴더 설정을 선택해 경로 옵션을 인식하지 못했고 시험 단계에서 실패했다. `service_checks.py`에서 설정 파일·프로젝트 루트·테스트 경로를 명시하도록 수정했다. 실패 로그는 보존했고 별도 `clean_v2/`에서 전체 절차를 다시 실행해 종료코드 0을 확인했다. 이전 실패를 성공으로 덮어쓰지 않았다.

## 4. 수치 재현과 보존

- 작업 전 기록한 원본·기존 산출물 **185개 파일 모두 변경 없음**: `release_audit/release_audit.json`.
- 새 분할은 개발 1,913행, 홀드아웃 480행이며 기존 분할 CSV와 바이트 단위 일치. SHA-256: `e26a82c58d0e86952b8557c2e8542f816f64db8ed49d15a4a450ef7a86b5efc7`.
- 기존 환경 CPU 재실행의 5개 수치 CSV와 보정 재실행의 4개 수치 CSV가 각각 기존 참고 결과와 바이트 단위 일치했다.
- 별도 코드 복사·새 venv에서 공식 입력을 명시해 실행한 `clean_v2/`도 분할과 CPU 5개 CSV 모두 동일했다. 과거 outputs는 복사하지 않았고 생성 완료 후 외부 참고 결과와 비교했다.
- 독립 결과 검사기로 OOF 40,173행의 식별자·라벨·그룹·fold를 확인하고 전체/설비별 지표 63행을 절대 허용 오차 `1e-12`로 재계산했다: `cpu_verification/verification.json`, `clean_v2/result_verification/verification.json`.

CPU 비교 대상은 기존 7후보×3seed×5fold다. CSV는 `oof_predictions`, `comparison_summary`, `condition_slices`, `metrics_by_fold`, `metrics_by_seed_machine`이다. 보정 비교 대상은 `nested_oof_predictions`, `nested_split_manifest`, `reliability_bins`, `conditional_errors`다. fold/조건별 표의 별도 검사기는 해시 무결성만 검사하며, 여기서는 전체 재실행의 바이트 동등성을 추가 확인했다.

재현 환경은 같은 컴퓨터의 macOS arm64·Python 3.12.7이다. 다른 OS/하드웨어의 수치 동등성, 미래 일반화, 성능 개선을 검증한 것은 아니다. 실행 중간 실패·시각·로그·새 코드 해시는 수치 동등성 대상과 구별한다.

## 5. 실제 실행 명령

프로젝트 최상단에서 실행했다. 아래 결과 경로는 이미 존재하므로 **재실행 시 새 폴더명**으로 바꾼다.

```bash
.venv-compare/bin/python service_checks.py --layer all --output-dir outputs/service_dev_20260926/checks_final
.venv-compare/bin/python service_checks.py --layer all --no-data --output-dir outputs/service_dev_20260926/checks_no_data
.venv-compare/bin/python verify_clean_reproduction.py --data-dir '1. 사출성형기 AI 데이터셋' --output-dir outputs/service_dev_20260926/clean_v2
.venv-compare/bin/python verify_service_release.py --evidence-dir outputs/service_dev_20260926 --output-dir outputs/service_dev_20260926/release_audit
.venv-compare/bin/python -m moldguard_service.api --port 8765
.venv-compare/bin/python service_probe.py --output-dir outputs/service_dev_20260926/api_probe
```

분할·CPU·보정 개별 실행 명령은 [최상단 실행 가이드](../MoldGuard_서비스_실행가이드.md)를 참고한다. 격리 실행의 설치·분할·비교·검사에 사용한 정확한 절대 경로 명령과 종료코드는 `clean_v2/execution.json`에 남아 있다.

## 6. 화면·API와 남은 조건

실제 과거 순위 71,180행의 action 집계는 RG3 35,941행, CN7 OOD 19,607행, CN7 라벨 미확정 15,632행이며 전량 기존 검사를 유지한다. 제품/샷/캐비티/예측 시각은 추정하지 않는다. 데이터 없는 화면/API는 빈 상태와 미산출을 반환한다.

로컬 브라우저에서 준비 상태·순위·지표 및 데이터 없는 상태를 확인했다. 기존 캡처 `model-validation.jpg`는 좁은 뷰포트의 지표 화면 일부이며 전체 화면·모든 시나리오를 증명하는 자료는 아니다. 자동 API 점검은 엔드포인트별 5회 모두 통과했다. 측정 p95는 약 4.27~7.41초로, 반복 파일 검사 비용의 최적화 여지가 있다. 운영 부하/모델 추론 속도 시험은 아니다.

라벨 방향, 평가 단위, 제품/샷/캐비티 관계, 도착/검사 시각, 원시 단위·변환기, 후속 기간 라벨이 필요하다. 계약 기록 기능을 만들었다고 실제 계약이 확인된 것은 아니다. 현장 승인 API·검사 생략·자동 제어는 비활성이다.

다음 개발 순서는 [고도화 문서 안내와 다음 작업](../고도화_문서안내_및_다음작업.md)에 정리했다. 외부 공유 시 로컬 증거 경로만으로 상대가 로그를 볼 수는 없으므로, 공개 가능한 집계·로그를 별도 검토해 묶어야 한다. 원본/행 단위 자료의 외부 전송은 수행하지 않았다.
