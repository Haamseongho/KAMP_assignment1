## 제공 파일과 실제 저장소 대조

추가된 docs/12~14, `config/service_policy.example.json`, `config/acceptance_criteria.example.json`, `source_manifest.json`, 붙여넣은 요청을 읽었다. 기존 03·04·05·07·08 보고서, 고도화 로드맵과 실제 코드를 대조했다. 제공된 명세는 첫 배치를 MG-001~005로 한정하고 이후 배치를 별도로 정의한다.

`source_manifest.json`의 `sources/` 경로는 원래 참고 패키지의 위치다. 현재 저장소에서는 03·04·07·08이 `docs/`, 로드맵이 최상단에 있으며, **5개 모두 제공 manifest의 SHA-256과 일치**했다. 가상의 sources 파일을 만들거나 제공 문서를 변경하지 않았다. 조사 증거: `outputs/service_dev_20260926/workspace_inventory.json`.

시작 당시 README의 이전 로드맵 링크 수정과 새 사용자 문서/설정이 미커밋 상태였다. 기존 내용을 보존하고 그 위에 기능·문서를 추가했다. 이번 작업에서 브랜치 전환·커밋·원격 푸시는 수행하지 않았다.

`moldguard.py`의 학습·추론 계산과 기존 480행 홀드아웃 결과는 수정하지 않았다. 새 비교 실행은 기존 후보의 수치 재현 확인이며 새로운 가설 실험이나 모델 개선 성과가 아니다. 과거 기본 경로도 유지하여 기존 호출과 호환한다.

## 범위 경계

LegacyResearch는 원본 행 ID·설비·원본 해시로 추적하고 물리 제품/샷/캐비티 ID와 실제 시각은 null로 남긴다. OperationalObservation은 별도 구조/시점 차단 검사만 있으며 실제 수신·승인 API는 없다.

이번 화면은 기존 결과 조회다. 실패조건 상세, 상충 그룹 탐색 UI, 점검 업무와 검사 결과 정정의 저장 흐름은 후속 MG-006~009에서 구현할 대상이다. 코드가 없는 항목을 메뉴로 연출하거나 완료로 보고하지 않는다. 읽기 전용 정책으로 현재의 검사 흐름은 변경되지 않는다.
