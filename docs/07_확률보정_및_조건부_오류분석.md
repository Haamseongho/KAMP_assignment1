# 확률보정 및 공정조건별 오류 — 추가 개발 검증

검토일: 2026-09-22. 기존 모델·홀드아웃·노션 공유 ZIP을 바꾸지 않은 별도 연구 기록이다. **보정된 모델이 더 좋은 최종 모델이라는 결론은 내리지 않았다.** 과도한 원점수는 줄었지만 단순 발생률 예측 대비 개선은 불확실하며, RG3의 구분 능력도 부족하다.

## 1. 검증 범위와 누수 방지

- 실제 라벨 데이터의 고정 개발 영역만 사용: 1,913행, 동일 공정값 957그룹, 숫자 라벨 1은 33행. 기존 홀드아웃 480행은 이 실험의 학습·평가에 사용하지 않았다.
- 원본 파일 SHA-256과 `outputs/local_runs/20260922-share-final/split_manifest.csv`를 확인한 뒤 기존 외부 5개 fold를 그대로 사용했다. 같은 설비·동일 공정값 그룹을 분리하지 않는다.
- 각 외부 학습 영역 안에 별도 그룹 기반 5-fold를 만들었다. 내부 OOF 예측으로 sigmoid 보정기를 적합하고, 외부 검증 행은 최종 예측에서만 사용했다. 표준화도 각 모델의 학습 영역 안에서 적합한다.
- 비교 대상은 외부 학습 영역의 전체 발생률 상수, 기존 균형 가중 로지스틱 원점수, 해당 모델의 sigmoid 보정값이다. 보정기는 `ensemble=False`이며 기반 모델은 해당 외부 학습 영역 전체로 다시 적합한다. [scikit-learn 1.5 API](https://scikit-learn.org/1.5/modules/generated/sklearn.calibration.CalibratedClassifierCV.html)
- 공정조건의 중앙값과 오류분석용 F2 임계값도 외부 학습 영역에서만 결정했다. 임계값 선택은 내부 OOF 예측을 사용한다.

제한: 이 개발 데이터는 이미 모델 선택에 사용됐다. 따라서 **모델 선택 이후의 탐색 분석**이며 독립적인 미래 성능 검증이 아니다. 동일 관측값 차단은 실제 샷·캐비티·시간 분리를 대체하지 못한다. 원본 파일의 사전 정규화 범위와 변수 도착 시각은 여전히 미확정이다. `PassOrFail=1`의 의미도 미확정이므로 아래의 양성은 모두 **숫자 라벨 1**을 뜻한다.

## 2. 확률 손실과 순위 성능

전체 개발 OOF 결과. AP는 높을수록, Brier와 Log loss는 낮을수록 좋다. Top 10%는 192행에서 찾은 라벨 1의 수다.

| 비교 대상 | AP | Brier | Log loss | 평균 점수 | Top 10% 발견 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 학습 발생률 상수 | 0.016579 | 0.016954 | 0.087161 | 1.7250% | 2/33 |
| 기존 균형 가중 로지스틱 | 0.115419 | 0.160977 | 0.484222 | 29.6837% | 9/33 |
| 중첩 sigmoid 보정 | 0.061731 | 0.016695 | 0.080736 | 1.7734% | 8/33 |

관측 양성률은 1.7250%다. 원점수의 평균 29.68%를 불량 발생 확률로 해석하면 안 된다. 보정 후 평균이 가까워졌다는 사실만으로 전 구간의 확률 신뢰성이 입증되지는 않는다. Brier는 보정뿐 아니라 구분 능력과 데이터 불확실성도 반영하므로 신뢰도 구간표를 같이 봐야 한다. [scikit-learn 확률보정 설명](https://scikit-learn.org/1.5/modules/calibration.html)

상수 모델의 Top-K는 동점 처리에 영향을 받으므로 유용한 정렬 능력으로 해석하지 않는다. 보정 모델의 0.5 임계값 F1은 0이다. 희귀 양성 문제에서 보정 전후에 같은 0.5를 적용하는 것은 운영 임계값 비교를 대신하지 못한다.

| 설비 | 평가 행 / 양성 | 원점수 AP | 보정 AP | 상수 Brier | 원점수 Brier | 보정 Brier |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| CN7 | 967 / 13 | 0.286265 | 0.248356 | 0.013279 | 0.083129 | 0.012450 |
| RG3 | 946 / 20 | 0.023058 | 0.022153 | 0.020710 | 0.240553 | 0.021035 |

RG3 보정 Log loss도 0.105875로 상수 0.102870보다 나쁘다. 원점수의 과신을 완화했지만, 실질적 예측 신호를 확보했다고 볼 수 없다.

### AP 하락 해석에 관한 주의

외부 fold별 AP는 원점수와 보정값이 각각 동일했다: 0.320841, 0.046458, 0.109444, 0.026090, 0.189913. 이 실행에서는 각 fold 안의 순위가 보존됐다. 전체 OOF를 합치면 서로 다른 fold의 보정 함수와 점수 척도가 섞이므로 합산 AP는 달라진다. **“sigmoid 보정은 항상 단일 모델의 순위를 망친다”는 결론이 아니다.**

### 개선 불확실성

동일 공정값 그룹 단위 paired bootstrap 2,000회, 차이는 `보정 Brier − 비교 Brier`다.

| 비교 | 차이 | 95% 구간 | 해석 |
| --- | ---: | --- | --- |
| 보정 − 원점수 | −0.144282 | [−0.159581, −0.130269] | 원점수의 큰 확률 손실 완화 |
| 보정 − 발생률 상수 | −0.000258 | [−0.000896, +0.000167] | 0 포함, 상수보다 우수하다고 확정 불가 |

고정된 OOF 예측을 재표집한 구간이다. 전체 재학습·모델 선택의 불확실성까지 포함한 독립 성능 보증이 아니다.

## 3. 어떤 조건에서 실패하는가

아래 오류는 기존 홀드아웃의 TP/FN/FP가 아니다. 각 외부 학습 영역 내부 OOF에서 고른 F2 임계값을 **원점수**에 적용한 개발 OOF 진단이다. `FN/(TP+FN)`은 놓친 양성 비율, `FP/(FP+TN)`은 음성 중 오경보 비율이다.

단일 조건 요약:

- CN7 `Clamp_Close_Time`이 학습 중앙값보다 큰 영역에 개발 양성 13행이 모두 있었다. TP 9, FN 4이며 음성 430행 중 FP 68(15.81%)이었다. 이하 영역은 524행 중 양성이 0행이지만 무불량 영역이라는 증거는 아니다.
- RG3 `Max_Switch_Over_Pressure`가 학습 중앙값보다 큰 영역은 음성 400행 중 FP 149(37.25%), 이하 영역은 음성 526행 중 FP 105(19.96%)였다. 두 영역 모두 양성을 놓쳤다: 각각 FN 5/8, FN 9/12.

RG3의 두 압력 조건을 함께 나눈 상세 결과:

| Max_Injection_Pressure | Max_Switch_Over_Pressure | 행 / 양성 | TP / FN | FP / TN | 음성 중 오경보율 |
| --- | --- | ---: | ---: | ---: | ---: |
| 중앙값 초과 | 중앙값 초과 | 326 / 7 | 2 / 5 | 114 / 205 | 35.74% |
| 중앙값 초과 | 중앙값 이하 | 106 / 4 | 1 / 3 | 31 / 71 | 30.39% |
| 중앙값 이하 | 중앙값 초과 | 82 / 1 | 1 / 0 | 35 / 46 | 43.21% |
| 중앙값 이하 | 중앙값 이하 | 432 / 8 | 2 / 6 | 74 / 350 | 17.45% |

각 중앙값은 해당 외부 학습 영역의 해당 설비에서 계산했다. 동점이 많아 행 수가 절반씩 나뉘지 않는다. RG3의 모든 결합조건은 양성이 10행 미만이므로 FN 비율이 특히 불안정하다. 양성 1행을 맞힌 조건의 FN=0도 완전 검출을 뜻하지 않는다.

이것은 **조건부 연관성**이다. 인과적 상호작용, 물리 단위의 최적 설정값, 실제 설비 제어 규칙이 아니다. 이미 정규화된 열의 상대 구간이므로 압력이나 시간을 바꾸라는 처방을 만들지 않는다. 모든 단일/결합 조건의 행 수·그룹 수·오류 수는 `conditional_errors.csv`에 남겼다.

## 4. 코드·산출물·재현

- 실행 코드: `calibration_diagnostics.py`
- 고정 환경: Python 3.12.7, `requirements-model-lock.txt`, CPU
- 첫 실행: `outputs/calibration-review-20260922/`, 로그: `outputs/calibration-review-20260922.log`
- 독립 반복 실행: `outputs/calibration-review-20260922-repro/`, 로그: `outputs/calibration-review-20260922-repro.log`
- 자동 테스트: `tests/test_calibration_diagnostics.py`의 추가 7개와 기존 11개
- 검증 도구: `verify_calibration_review.py`; 두 실행의 7개 파일 바이트 동일 여부, 각 파일 해시 명세, 코드·분할 해시, 기존 모델·결과·공유 ZIP 불변성 및 전체 테스트를 확인한다.
- 검증 영수증: `outputs/calibration-review-verification.json`

실제 검증 결과: **18 tests passed**, 검증 항목 **37/37 통과**. 두 독립 실행의 7개 산출물 SHA-256이 모두 같았고, 기존 코드·모델·수치 결과·그림·노션 공유 ZIP의 해시도 보존됐다. 이 일치는 현재 고정 CPU 환경의 재현 확인이지 다른 운영체제나 미래 데이터의 성능 보증은 아니다.

산출물은 OOF 행별 점수, 내부/외부 분할 명세, 신뢰도 구간, 조건부 오류, 수치 보고서, 연구용 보정 모델, 해시 목록이다. `calibrated_research_model.joblib`은 개발 영역에만 적합했으며 `deployment_approved=False`다. 기존 `outputs/moldguard/model.joblib`과 검사 대기열을 교체하지 않았다.

로컬 재실행 예시(폴더/영수증이 이미 있으면 새 이름을 사용):

```bash
cd /Users/hamseongho/Documents/ChatGPT/KAMP
.venv-repro/bin/python calibration_diagnostics.py --output-dir outputs/calibration-user-first
.venv-repro/bin/python calibration_diagnostics.py --output-dir outputs/calibration-user-second
.venv-repro/bin/python verify_calibration_review.py --first outputs/calibration-user-first --second outputs/calibration-user-second --output outputs/calibration-user-verification.json
```

자동 테스트 중 저장 산출물 검사는 기준 연구 폴더 `outputs/calibration-review-20260922/`를 확인한다. 새 폴더 쌍은 검증 도구가 파일 해시를 비교하며, 원본 연구 폴더를 덮어쓰지 않는다. 이 코드는 합성 제조데이터를 만들지 않는다. 단위 테스트의 소수 경계값은 계산 검사용이며 대회 성능 산출에 쓰지 않는다.

## 5. 결정과 남은 조건

1. 기존 모델·검사 유지 정책을 그대로 보존한다. 이번 보정 모델의 운영 채택은 보류한다.
2. 라벨 코드북, 실제 시각·샷/제품 키, 사전 정규화 이력, 후속 기간 라벨을 받으면 데이터 계약을 먼저 검증한다. 세부 요청은 [추가 데이터 명세](04_추가데이터_요청명세.md)에 있다.
3. 후속 기간을 모델 선택에 사용하지 않고 평가 영역을 먼저 동결한다. 보정은 개발/보정 영역에서만 적합하고, 설비별 확률 손실·발견율·오경보를 새 평가 영역에서 비교한다.
4. 현재 노션 공유 페이지와 ZIP은 앞서 게시한 버전으로 유지했다. **이 추가 연구 문서와 코드는 아직 그 ZIP/노션에 포함하지 않았다.** 대회 사이트에는 제출하지 않았다.
